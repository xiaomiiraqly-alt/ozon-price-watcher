## Проверено локально

- 81 тест: исходные проверки и регрессии для перечисленных ошибок.
- Настоящий MCP stdio-сеанс с тестовым FastMCP-сервером: словарь и список результатов, завершение дочернего процесса.
- Установка Python-пакета, сборка wheel, `pip check`, `ruff` (F/B/ASYNC), `bash -n`, `git diff --check`.
- Подготовка настоящего upstream checkout на фиксированном commit; повторный запуск и отказ от перезаписи локальных изменений проверены отдельным тестом.
- Поиск путей `.env`, пользовательских данных и ключей, а также типичных шаблонов Telegram-токена/приватного ключа в истории Git: совпадений не найдено. Это ограниченная проверка шаблонов, не доказательство отсутствия любых секретов.
- После обновления MCP до 1.30.0, PyJWT до 2.15.1 и multidict до 6.9.1 `pip-audit` не нашёл известных уязвимостей в разрешённых Python-зависимостях приложения. Проверка относится к фактически установленным версиям на дату аудита.

Минимальные версии безопасности закреплены в `pyproject.toml` и Dockerfile gateway. Основания: [MCP SDK](https://github.com/modelcontextprotocol/python-sdk/security/advisories/GHSA-rwrf-2pqf-9j8j), [PyJWT](https://github.com/jpadilla/pyjwt/security/advisories/GHSA-gvp8-978c-rx2q), [multidict](https://github.com/aio-libs/multidict/security/advisories/GHSA-54p9-h82j-f925).

## Границы проверки

Реальные учётные записи Ozon, Telegram-токен, VPS и его AWG-маршрут в этой среде недоступны. Авторизация в Ozon, доступность IP, ACME-сертификат и фактический маршрут проверяются после развёртывания на VPS. Локально нет Docker daemon: сборка обоих образов и проверка Compose вынесены в GitHub Actions.

Проверка зависимостей Python не покрывает системные пакеты Docker-образов, nginx, Caddy, GOST и AWG. Уведомления об изменении цены не являются способом покупки или автоматического пересчёта заказа.

Изменение правил базовой цены применяется к последующим наблюдениям. Исторические записи с ошибочно выбранной базой нельзя автоматически отличить от корректных без сверки с заказом; массовая перезапись истории не выполнялась.

## Обновление VPS

Сначала сохраните защищённую резервную копию `.env` и `data/`. Затем в рабочем checkout:

```bash
git pull --ff-only
./scripts/prepare.sh
docker compose up -d --build
./scripts/check_network.sh
```

После обновления: `/status`, новый `/connect` при необходимости, затем `/sync`. Существующие HTTPS-настройки на VPS и пользовательские секреты в репозитории не изменялись.

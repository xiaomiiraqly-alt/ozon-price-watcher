# Ozon Price Watcher v0.4 — приватный семейный бот

Один Telegram-бот для владельца и приглашённых близких. Каждый подключает **свой** аккаунт Ozon через личную одноразовую HTTPS-ссылку. Корзины, заказы, цены, уведомления, история и настройки разделены по числовым Telegram ID. Никаких общих Ozon-cookie.

## Возможности

- Одноразовое приглашение близкого через `/invite` (только владелец, ссылка на 7 дней, не более 12 активных пользователей, включая владельца).
- `/connect` — персональная HTTPS-ссылка (10 минут, одноразовая). Номер и код Ozon вводятся на отдельной странице; **не в Telegram**. HTTPS-сессия ограничена 20 минутами и числом попыток.
- Для каждого человека выделяется отдельный процесс Ozon MCP со своим браузерным профилем, backup и cookie-файлами (`data/ozon/users/TELEGRAM_ID`). Все Ozon-запросы идут напрямую с VPS.
- Мониторинг корзины и заказов до получения. Цена оформленного заказа сохраняется как исходная. Разные посылки одного заказа учитываются отдельно.
- Порог снижения по умолчанию 100 ₽, персональный общий `/default` и индивидуальный `/limit`.
- Отдельная история цен, антидублирование уведомлений и ручное добавление по ссылке.
- `/users`, `/revoke ID` — управление приглашёнными. При отзыве доступ закрывается, бот стирает записи и запрашивает удаление профиля Ozon. Если gateway недоступен, он честно предупреждает, что профиль нужно удалить вручную после остановки сервиса.
- `/disconnect confirm` — самостоятельно отвязать аккаунт с удалением профиля и истории.

**Важно:** API покупателя Ozon официально не предоставлен. Используется сторонний [ozon-mcp](https://github.com/Alexander-Zhukov/ozon-mcp), основанный на внутренних интерфейсах Ozon. Работа может нарушаться при изменениях Ozon, блокировках IP или способа входа. Не включены покупка, отмена или оплата заказов. Это не коммерческий SaaS.

## Разделение сети

```
Пользователь ──Telegram──> [bot, только private_backend]
                                 │
                Telegram API <──[SOCKS5 GOST + AWG-клиент]──> [AWG Router → зарубежный выход]
                                 │
                  [внутренний API ozon-gateway]──> [индивидуальный MCP-процесс]──> [IP VPS → Ozon]

Пользователь ──HTTPS──> [Caddy или существующий reverse proxy]──> [login-web]
                                                                   │
                                              одноразовый токен + профиль пользователя
```

`bot` не подключён к `direct_egress`; SOCKS5-соединение GOST привязано к `awg0` и не должно переключаться на прямой доступ при обрыве VPN. `ozon-gateway` использует собственный прямой Docker-маршрут, **не AWG**. Порты MCP/gateway наружу не публикуются, внутренний gateway дополнительно защищён длинным случайным секретом; gateway проверяет разрешение пользователя в базе при каждом запросе. Панель и конфигурация установленного AWG-Router не модифицируются.

## Требования

- VPS с Docker Engine, Docker Compose, Git, Python 3; место на диске для Chromium и его профилей.
- Созданный бот в @BotFather и ваш числовой Telegram ID.
- Отдельный профиль клиента из панели AWG-Router: `vpn://`, `awg://` или локальный `.conf`.
- Для самостоятельной авторизации близких — **HTTPS-домен**, указывающий на этот сервер (например, `ozon.example.org`). Если на портах 80/443 уже работает ваша панель или другой reverse proxy, нужно добавить в него виртуальный хост для этого домена. Установщик не будет останавливать существующий сервис.

### Первая установка на VPS

Распакуйте ZIP в `/opt/ozon-price-watcher` и в SSH-терминале выполните:

```bash
cd /opt/ozon-price-watcher
chmod +x install.sh
./install.sh
```

Мастер спросит: Telegram-токен (скрытый ввод), Telegram ID владельца, **домен HTTPS-входа (можно пропустить)** и ссылку/конфиг AWG (скрытый ввод, поддержка длинных AWG 3.x ссылок). Всё сохраняется локально в `.env` и файле клиентского профиля AWG с правами `600`; gateway-secret создаётся случайно автоматически.

Для настройки без запуска контейнеров: `./install.sh --no-start`. Мастер остаётся интерактивным.

`prepare.sh` клонирует внешний `ozon-mcp`, готовит каталоги, переносит при обновлении старый Ozon-профиль владельца в `data/ozon/users/OWNER_ID` и сохраняет прежнюю базу SQLite. Новые таблицы БД создаются автоматически. **Перед обновлением работающего бота сделайте защищённый бэкап каталога `data/` и `.env`.**

При свободных 80/443, заданном домене, установщик запускает опциональный сервис `family-https` (Caddy с автоматическим TLS). Домен должен разрешаться на VPS, входящий TCP/80 и TCP/443 должны быть открыты. Если порты уже заняты, запускается только `login-web` с HTTP на локальном интерфейсе `127.0.0.1:8765`, а существующий HTTPS-proxy следует настроить **вручную** для `https://ВАШ_ДОМЕН → http://127.0.0.1:8765`. Не публикуйте порт 8765 в интернет: там HTTP без TLS. При отсутствии домена `/connect` выдаст инструкцию, но не создаст небезопасную HTTP-ссылку.

Проверка сети:

```bash
docker compose ps
./scripts/check_network.sh
```

Ожидается, что публичный IP через SOCKS5 (Telegram) отличается от прямого IP VPS (Ozon). Один лишь результат IP-теста не доказывает маршрут конкретного адреса Telegram: убедитесь, что индивидуальный клиент AWG-Router принудительно выводится через нужный зарубежный канал. **Не используйте `/sync`, пока сеть не проверена.**

### Как пригласить близких

1. Владелец отправляет `/invite` боту в личном Telegram-чате.
2. Владелец пересылает полученную одноразовую ссылку близкому.
3. Близкий открывает ссылку, нажимает Start и получает доступ. Он отправляет `/connect`.
4. Бот возвращает индивидуальную ссылку на HTTPS-сайт. Близкий открывает её, вводит **свой** телефон/email Ozon и полученный от Ozon код.
5. После подтверждения отправляет `/status`, затем `/sync`. Можно настраивать собственные пороги и список товаров.

Каждое новое приглашение работает только один раз; чужие товары и Ozon-аккаунты пользователям не видны. Управление настройками производится исключительно в личных сообщениях с ботом. В группах команды игнорируются.

## Telegram-команды

| Команда | Действие |
|---|---|
| `/start`, `/help` | Начало и справка |
| `/connect` | Одноразовая HTTPS-ссылка для своего Ozon |
| `/status` | Состояние **своего** Ozon и настройка |
| `/sync` | Принудительная проверка **своей** корзины и заказов |
| `/items [cart\|order\|manual] [N]` | **Свои** позиции по 12 на страницу |
| `/add ССЫЛКА_НА_OZON` | Ручное наблюдение за товаром |
| `/default 100` | Общий порог снижения — только у себя |
| `/limit SKU 300` | Порог для всех своих наблюдений данного SKU |
| `/limit #ID 300` | Порог для конкретной своей позиции |
| `/limit #ID default` | Вернуть персональный общий порог |
| `/pause SKU`, `/resume SKU` | Остановить/возобновить свои уведомления |
| `/remove SKU` | Удалить собственное ручное наблюдение |
| `/mode bank`, `/mode regular` | Способ сравнения цены карточки |
| `/disconnect confirm` | Отвязать свой Ozon и стереть историю |
| `/invite` | **Владелец:** одноразовое приглашение |
| `/users` | **Владелец:** список участников без их покупок |
| `/revoke ID` | **Владелец:** закрыть доступ близкому, удалить его данные |

Общий порог: по умолчанию 100 ₽, индивидуальный порог применяется к конкретной позиции или SKU. После уведомления о снижении на 100 ₽ новое уведомление возникает только при **ещё одном снижении** не менее чем на 100 ₽ от предыдущего уведомления. Переоценка заказа не меняет уже списанные деньги автоматически.

## Диагностика и ограничения

```bash
docker compose logs -f --tail 100 bot
docker compose logs -f --tail 100 ozon-gateway
docker compose logs -f --tail 100 login-web
./scripts/check_network.sh
python -m unittest discover -s tests -v
```

В `.env` хранится `GATEWAY_TOKEN`, и **он не должен быть общедоступен**. Профили Ozon содержат сессионные данные, эквивалентные доступу к учётным записям. Резервные копии храните зашифрованно. Никогда не публикуйте `.env`, каталог `data/`, ключи AWG и cookie в GitHub. Не включайте `network_mode: host` для AWG-клиента. Не открывайте порт 8085 (gateway) или 8086 (web) напрямую в интернет.

**Ограничение проверки:** локальные модульные тесты не заменяют проверку реальной авторизации Ozon, работы Chromium, получения разных аккаунтов и VPN-маршрута. После первого развёртывания их нужно проверить на двух тестовых учётных записях, прежде чем подключать всех близких. Каждый новый активный аккаунт расходует память на отдельную сессию Chromium; оценивайте нагрузку на VPS.
